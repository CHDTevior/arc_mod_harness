# 用追问把愿望变成目标

“Grill-me” 在这里指有针对性地把模糊之处问清楚，不是考作者技术术语。
AI 负责调查工具和实现路线，人类负责选择想要的感觉、提供看得见的反例。

## 第一轮

先读已有信息，只补最重要的空白：

1. **你想改哪个游戏的谁？别人第一眼应该看出哪三个变化？**
2. **最在意哪种画面？** 正常战斗、必杀特写、入场、胜利、人物展示，可排序。
3. **你手里已有哪张图或哪个模型？** 可以是一个局部；说明想借哪里，不喜欢哪里。

不要把所有问题一次发出。已有角色和参考时，第一轮可以只问“这张图里最不能丢的是什么？”
没有参考时，先给两个文字方向，再生成最多三种低成本概念。初版三视图应及时揭示原图
未画的脚、背面、发型根部、衣服开口；别把 AI 的补全当成作者已选定的设计。

已有目标角色三视图的全角色替换，先用实际游戏截图结合它生成整幅目标，让人先看游戏
画风中的观感，再定底模和分件。示例见 [特蕾西娅 → Dizzy](theresa-dizzy-example.md)。
如果用户只是在讨论“假如做”，就解释并完善计划，不自动发起生成或制作实际 MOD。

## 按答案深入

| 作者说 | 下一问 | 可以继续的独立工作 |
|---|---|---|
| “可爱一点” | 更圆的脸、更短下脸还是更柔的眼神？哪张图最接近？ | 提取原模型、做头部三视图 |
| “死鱼眼” | 平的是上边缘还是下边缘？黑瞳孔要露出多少？要疲倦还是挑衅？ | 标注眼眶、上下睑、虹膜和黑瞳孔 |
| “两眼不在看一个东西” | 看镜头、略向下还是看手/道具？标出想固定的一只眼 | 核对原相机、头部倾斜和遮挡 |
| “身体按这个来” | 借曲线还是直接用网格？哪些部位比例不能改？ | 比较连续拓扑、rest pose、骨架和材质 |
| “有同角色 nude MOD” | 这份身体与目标相比，最想保留和修改哪些比例？ | 实测体型/关节，验证 rig、权重和原动作，合适则复用 |
| “这个装饰不知道怎么建” | 要保留的轮廓、厚度和安装位置是哪几处？ | 单件设计图，选择简模、供体或 Tripo 结构参考 |
| “8K 图怎么还是糊” | 哪个实际镜头和局部最明显？ | 检查源 AA、有效 UV 密度、导入/压缩和 GPU 驻留，不先加尺寸 |
| “更有皮肤光泽” | 小面积亮点还是宽柔光？给同一光线下的参考 | 检查原材质通道、法线和压缩结果 |
| “都放进包” | 目标游戏版本、语言、配色、可选件是什么？朋友怎样安装？ | 建立依赖清单、检查管理器布局 |
| “先给我视频选” | 哪一个关键镜头最能决定？ | 同相机、同时长渲染候选，保留编号 |

每轮复述四项：**想要 / 保留 / 未定 / 用什么画面判断**。有矛盾时展示冲突：
“新参考的下眼缘更平，旧版保留笑眼弧度。这里采用哪一个？”不要偷偷取平均。

## 材料按需要索取

- 视觉：原始参考图、必要局部、已经否决的例子、目标镜头；优先本地文件的原分辨率。
- 模型：原游戏角色及骨架、相似模型、许可或作者说明、是否可直接复用；参考研究与再发布分开。
- 动作：原动作、头/身体切换、武器挂点、关键帧、相机、口型/语音触发；不要求新手先全部懂。
- 运行：游戏及版本、工具位置、已装 MOD、安装管理器；AI 能只读发现的不要反复让人填写。
- 声音：语言、源音频到目标事件映射、处理参数、可用范围、响度和时长；音色模型不自动随 MOD 发布。
- 交付：完整包还是补丁、旧版保留、A/B 是否仅供审查、朋友试用还是公开发布、耗时/费用边界。

不知道的字段写“待检查”，不要编版本号。与当前一步无关的字段可以推迟。实际花费外部服务
费用或扩大外部写入范围前按已有授权处理；不要把每一次本地渲染都变成权限问卷。

## 阶段性人类介入

| 时机 | 给人看的东西 | 人类决定 | AI 自主完成 |
|---|---|---|---|
| 概念刚成形 | 全身三视图，补全部位单列 | 人设、轮廓、颜色和优先级 | 工具链探路、资料整理 |
| 穿衣前 | 连续身体 rest pose 正侧背，尺度对照 | 体型、头身、肩颈与胯宽 | 拓扑、权重初查 |
| 衣服试穿 | 抬臂、弯腰、持武器 | 宽松度、层次和剪影 | 缝合、局部蒙皮、碰撞诊断 |
| 动作/表情候选 | 同镜头 A/B/C 与 2D 控制点 | 气质、眼神、嘴型 | 求解、导出、过渡检查 |
| 材质和全配色 | 默认色与差异最大的颜色，鞋/眼镜细节 | 亮度、肤感、配色分配 | 通道/压缩/依赖验证 |
| 安装后 | 游戏中的具体动作、语音和 UI | 是否符合实际游玩感受 | 记录包哈希、复现和修复 |
| 发布前 | 选定版、已测范围、图片和回滚说明 | 发试用还是发布 | 构建已授权的包及素材 |

允许人类随时打断改方向。记录为新的目标版本，让相关旧审查失效；未相关的制作成果仍保留。
不要让作者负责猜哪些骨头该移动，也不要把“感觉不对”视为没有价值的反馈。
