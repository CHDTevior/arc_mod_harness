# 假设立项：特蕾西娅 → Queen Dizzy

这是用于说明思考顺序的假设案例，**尚未制作这个 MOD，也未选定服装版本、找到可用 nude
底模或生成图片**。已知用户想做特蕾西娅替换 Dizzy；不能把这些未知项写成已批准方案。

## 1. 先让作者看“放进游戏是什么感觉”

第一轮只补关键问题：“用哪套特蕾西娅造型？这套设计里最不能丢的三点是什么？”
有三视图就直接读；没有则从作者选定的原画补正侧背，并把背面、鞋、衣服开口等补全单列。
外观目标优先，工具链的只读调查可同时进行；不先开做整个人体或付费生成一堆网格。

准备两组输入：

- **Dizzy 实际游戏画面**：一张能看完整身体的普通战斗姿态，一张常用的表情特写；必要时
  再加最易冲突的动作。保留截图的版本、动作、镜头信息。
- **特蕾西娅选定三视图/原画**：说明哪张提供人设，哪张提供服装结构，哪些是 AI 补全。

以游戏截图为 edit 底图、三视图为人物设计参考，先做一版同镜头目标。保留原姿势、透视、
手脚落点、环境光和游戏画风，替换到所选角色设计；身体比例的有意改变单独标注。这样先
判断角色是否像、剪影能否读清、服装遮了多少身体、表情是否合适，再投资详细建模。

> 编辑附图 A（Dizzy 的实际游戏截图），参照 B/C/D（选定特蕾西娅三视图）呈现角色替换
> 后的目标观感。保持 A 的相机、动作、构图、手脚接触、场景和光照。借 B/C/D 的人物身份、
> 发型、服装及已确认配件；身体比例按【已选方向】。保留【明确保留对象】。未知设计不要
> 擅自加饰物。使材质与当前游戏的分层明暗和轮廓一致。这是概念目标，不是已运行的 MOD。

先比较完整画面，作者指出偏差后用局部 edit 修正，不每轮重新洗掉已经满意的部分。
如果还要比较气质，再做最多两三个同镜头方案。把 **目标图** 与 **实际游戏原图** 都留存。

## 2. 把确认的观感转成可建模规格

将已选游戏目标与三视图并列校对。三视图说明结构，动作目标说明游戏中的观感；两者冲突
就先问作者保留哪一个，而非把几张图平均。产物为：正侧背、体型保留项、重点面部/衣片
结构图、饰件清单、游戏镜头清单。

还要明确 Dizzy 原有的翅膀/伴生对象及特效如何处理：保留、换造型还是只改部分。这项
会改变工作量与依赖范围，不应在第一次主体试做时默默扩成全套替换。具体资源和驱动须
提取后确认，不能凭角色立绘推断各骨链和显示规则。

## 3. 比较体型，优先调查已有 Dizzy 绑定

先按 [底模选择](base-selection.md) 查找同目标角色、可用于本项目的连续身体候选，拿到
实际模型后比较头身、肩胯、胸廓、四肢比例和关节位置。仅凭角色设定身高不能判断可复用。

- 如果裸模接近所选目标，而且原 Dizzy 动作/原生导入表现可靠：保留它的 rig、可用权重
  和原动作，局部调整人体，再穿衣。这通常值得优先试。
- 如果只有身体曲线接近，绑定属于其他角色：将几何适配到 Dizzy rig，重新做权重测试。
- 如果人体已经好看，但抬臂、转身或接触出问题：先区分蒙皮与动作比例原因；确实需要时
  再做局部动作适配。不能把“全角色 MOD”理解成“一定要重定向全部动画”。

输出同尺度实际身体对照和一个简短选择理由；请作者审查的是体型。骨架兼容性由 AI 用
文件和测试调查，不要求新手凭直觉担保。

## 4. 按部件走不同路线

下面是待按选定服装确认的拆分方式，不是声称这些部件全部已经决定：

| 分件 | 起点 | 第一项能暴露问题的检查 |
|---|---|---|
| 脸、眼眉嘴 | 可控面部拓扑 + Dizzy 实际表情驱动 | 同镜头面部投影、眨眼与说话过渡 |
| 发根/刘海与后部长发 | 分层三视图、类似发型结构 | 转头遮眼、长发穿肩与后背 |
| 主衣片、裙摆/垂带（若采用） | 已定身体上制版、明确内外层 | 下蹲、抬臂、转体中的开口和穿插 |
| 角、胸针、扣件、鞋饰等（若采用） | 独立部件图；简模或 Tripo 结构参考 | 实际大小、厚度、安装面、与周围的接触 |
| 原角色特殊对象 | 已提取资源与动作 | 出现/消失时机、主体和对象同镜头关系 |

使用 [逐件 2D/3D 循环](component-workflow.md)：生成一个部件 → 看灰模/线框 → 渲染回
二维并 edit → 按目标重建/修拓扑 → 绑定到实际游戏驱动。服装和头发的蒙皮、辅助运动、
原动画适配分别确认。Tripo 不代替目标骨架和真实布料运动验证。

## 5. 收敛、验证、发布

用原游戏中的相机作主要验收；正交视图和夸大的诊断镜头用于找原因。先关键姿态，再看
受影响动画完整过渡。材质/光泽用实际 shader 检查，配色覆盖到鞋、饰件和特殊对象。
只有需求包含语音才做事件映射及对应触发试听。

最终图片必须来自选中版的实际渲染/游戏记录。打包所有非原生运行依赖，保留其他方案但
不混装。安装哈希、实机及朋友机器测试分别记录。让作者在目标、体型、部件外形、关键
表情、实际游玩与交付这几个有具体画面的节点介入，技术排查按授权继续。
