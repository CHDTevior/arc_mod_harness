# 返工时先分辨是哪一层出了问题

下表来自实际案例；参数和骨名不是跨游戏标准。优先做能区分假设的小实验。

需要实际操作顺序时读 [具体故障案例](incident-cards.md)：包含眼缘改错、入场瞳孔、
胜利嘴型的多轮求解、肩臂与手接触、黑枪，以及纹理/UV 的诊断分岔。
每例都说明错误假设如何被否定、实际改了哪些字段、怎么复查和哪些结论不能外推。

| 症状 | 常见误判/走过的弯路 | 有效诊断与修复路线 | 必须回归 |
|---|---|---|---|
| 胸腹接缝、腰部平台 | 继续增加窄接带圈数、只平均法线 | 查看供体连续曲面；完整胸腹腰髋适配；分别传递 UV、法线与权重 | 侧面、弯腰、扭转与材质 |
| 肩臂在动作里过宽 | rest pose 局部缩肩，数值窄了却更畸形 | 对照相似角色骨轴与比例；协同视觉动作适配；保持手/枪接触 | 待机、抬臂、胜利靠脸、枪套 |
| Blender 正确、引擎变形 | 只查全局 inverse bind | 查原生每骨局部 T/Q/S、单位和 root scale；制作导出副本 | 导入和 Cook 读回 |
| 权重细节消失 | 把导出器只给四权重当成游戏只有四权重 | 查真实 buffer、影响数、弱权重过滤与量化；量化后重评姿态 | 最大变形与未选顶点 |
| 眉毛扭曲/阴影重叠 | 镜像形状不管面绕序；只改眉骨、不看脸部 shader | 查三角 winding、法线、眉周控制色；用投影配合眉骨局部拟合 | high/low、眨眼与原特写 |
| 要改下睑却拉坏上睑 | 用相邻编号猜控制组 | 重建真实边界组、显示点 ID 和边；锁住上睑再拟合下边缘 | 两端眼角、黑瞳孔露出 |
| 两眼不协调/斗鸡眼 | 两只瞳孔机械对称或统一归一偏移 | 完整画面参考 → 原相机投影 → 头平面辅助 → 适量改位置/大小 | 转头、遮挡、自然速度视频 |
| 少数帧瞳孔碎裂/消失 | 当作纹理丢失，重画贴图 | 重放缩放/层叠；投影黑瞳孔三角采样与眼白深度；局部间距修复 | 整段入场、眼白/虹膜相交 |
| 外套腋下黑块 | 全面加亮或抹阴影 | 分开查看内外层穿插、法线、权重、阴影 pass；实际抬臂相机检查 | 转身、肘肩极值、轮廓 |
| 8K 图集，小纹身仍糊/锯齿 | 继续放大输出，忽略调色硬分类抹掉 AA | 量源图案像素与 UV 有效占地；保留连续调色覆盖，从源重新采样 | 手背/胸口、实际 4K/mip 与游戏镜头 |
| 原生预览大片色带 | 误当材质绑错/半精度 UV，重排整图 | 读当前 GPU mip 驻留；该次 64×64 到完整驻留的 A/B 定位 startup streaming | 当前游戏预算；不把隔离禁 streaming 当全局修复 |
| UV 零重叠但缺图/变形 | 只看重叠数，不看越界和方向密度 | R05 出界面被拒；全 UV 排布、域界/保存读回、棋盘格和真实覆盖一起查 | 拇指、胸腹大岛、原几何与权重不变 |
| 内衬串色/发梢黑点 | 全局重排或用黑色补未命中像素 | 查材料边界与微小岛，局部采样余量、真实源查询、有效样本与 padding | 真实 ID 栅格、压缩/mip、所有共享图 |
| 加独立身体图却污染头衣 | 每件各用完整 0–1，忽略原运行时共用材质 | 专用作者 UV 与最终共享图域分开；独立材质路线需同步实例/状态表 | 五件整体与每一张 companion 图 |
| 导入后颜色/阴影突变 | 对 Base 和控制 RGBA 全套通用 sRGB | 查实际 gamma、顶点色编码、零 alpha RGB 填充；原生读回 | Base/SSS 与控制通道分别核对、镜片单独 |
| 所有颜色枪变黑 | 只重画枪颜色，漏掉共享引用 | 检查枪材质继承链；身体新 detail 图污染共享原枪输入；独立保留枪 detail 并重定向 | 所有配色、特效/翻转/描边材质 |
| 皮肤缺少光泽 | 直接套一般金属度/粗糙度经验 | 用原 shader 对照参考 MOD；查高光强度/阈值控制、法线与实际压缩 | 多色、原相机、保持阴影/黑线通道 |
| 鞋和眼镜不随配色 | 只替换皮肤颜色 | 明确每部件配色归属；鞋面/鞋底/鞋带分开；恢复眼镜原配色链 | 所有颜色，不只默认色 |
| 嘴歪、闭嘴时翻唇 | 最后一帧的常量位移覆盖说话全段 | 各姿态拟合相对头部目标；约束面翻转和唇间距；high/low 各自基线 | 全变化区间、嘴角、牙舌、眼镜 |
| 编辑器 XboxOneZlib 报错 | 切到另一大版本引擎强行 Cook | 确认匹配引擎和缺失插件；在隔离项目诊断并关闭不需要的插件 | 同版本导入/Cook，不改全局配置 |
| 本机可以、朋友缺资源 | 把本机其他 MOD 或工程资源当原生 | 解析实际包依赖，区分 stock/自制/第三方最终资源，补齐非原生闭包 | 清洁安装、管理器 build 后再次核对 |

## 重要的二次困难

上述纹理问题的实际证据、阶段边界与完整修复过程见 [纹理 / UV / 材质专题](texture-uv-material.md)。
包括没有成立的半精度 UV 假设，以及 R05 零重叠却出界的失败，不能省略成“换 4K/8K 就好”。

修复一个症状后，检查约束是否互相冲突。例如嘴的表面没有翻面，仍可能上唇穿过下唇；
嘴线在最后一帧居中，仍可能在讲话帧反转。把“没有翻面”“唇间距”“自然神态”作为三个
不同检查，而不是一个总分。必要时换求解目标或加入约束，不继续堆相同方向的位移。

材质同理：源 PNG 的 alpha 正确，不代表导出查看器显示正确，也不代表 GPU 压缩后的
纹理相同。先识别哪个阶段丢信息，再修正确的阶段。保留 source/import/cook 的分层报告。

不要为了让检查变绿而提高阈值。只有证据表明原断言测错对象时才修改检查，并留下原失败、
调查过程、新断言的理由和仍存在的误差。独立于主观效果的硬检查应继续保留。
