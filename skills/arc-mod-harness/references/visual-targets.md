# 视觉参考、目标控制点与 2D 投影

## image gen / edit 的职责

生成目标供人选择；实际网格和游戏视频用来证明实现了多少。不能用 AI 修过的截图冒充
MOD 效果。调用宿主提供的图像工具并遵循它的技能和输入约定；本工具包不要求某一家 API。

**初始三视图提示模板：**

> 根据已附参考制作同一个角色的建模用正面、侧面、背面视图。统一头身比例、肩胯高度、
> 头发体积、服装接缝和配件位置，使用中性 rest pose、近似正交视角和一致光照。保留
> 【必须保留项】，采用【已选体型/气质】，补全【脚/背面等未知部分】。输出只作为概念
> 参考；不要用夸张透视、动作或阴影掩盖结构。若左右不对称，请在三个视角一致体现。

先看全身，再单独编辑头、手、鞋等重点。逐版保存，记录生成输入和作者选项；三视图中的
微小不一致要靠结构决策和真实 3D 视图解决，不是多生成几次就自然一致。

**局部表情编辑提示模板：**

> 编辑这张完整的【动画/帧号】截图作为目标参考。保持镜头、头姿、发型、身体和光照。
> 只调整【字符左眼/屏幕右眼】的【黑瞳孔、眼眶或眉】。两眼看向【目标】，黑瞳孔清楚
> 可见，避免斗鸡眼。下边缘采用【近直线，眼角圆滑回接】；上边缘和睫毛保持【指定形状】。
> 眉毛与眼睛共同表现【挑衅/慵懒】，不凭空改变脸型。生成的是参考，不是最终游戏成果。

审查生成结果有没有额外改嘴、扩大眼裂或“修美”身体。超出范围的部分不自动采纳。目标可以
只借它的视线关系；解算仍基于实际模型、骨架和相机。

## 先确定对象，再拉控制点

给每组命名：`eye_rim_upper`、`eye_rim_lower`、`iris`、`black_pupil`、`brow`、
`mouth_upper`、`mouth_lower`、`glasses`，再加 `character_L/R`。屏幕左右另记。
“眼睛最黑的圆形”是黑瞳孔，不是整个青色虹膜；“整个下边缘”不是上睑控制骨。

记录实际帧映射：原动画 key index、引擎采样时间、输出图片序号、视频时间、preroll 数量、
当前 high/low 模型及原相机参数。这些索引可能不同，最后显示帧不一定有同名 raw key。

## 投影和变形步骤

1. 从最终将被使用的源/导入模型取顶点、原生权重、bind/rest，重放实际层叠动作。
2. 蒙皮：`p_world = actor * Σ(weight_i * pose_world_i * inverse(rest_world_i) * p_bind)`。
   模型单位、坐标轴、相机父变换只转换一次。导入器量化了权重时用量化后的权重复核。
3. 以当前游戏相机做 `clip = projection * view * p_world`，透视除以 w。
   输出画面左上角原点：`u=(ndc_x+1)/2`，`v=(1-ndc_y)/2`。
4. 画整脸坐标图和头部平面图；标当前点、目标点、显式边及变动箭头。**无序边界点集不
   能按数组顺序连线**，只有真实拓扑边可以连接。后遮挡点不能当可见轮廓。
5. 先让人确认“这里是我要改的边缘”，再求小幅控制骨/形态变化。约束保留上睑、眼角
   连接、黑瞳孔可见性、邻近面、嘴唇间距、镜片厚度；改眉时一起看眉下阴影。
6. 在若干关键帧按当前姿态分别拟合目标，再平滑过渡。检查整个变化区间及两端。
7. 用实际原生相机渲染确认；全图看神态，近景看瑕疵，连续视频看穿插和表情节奏。

`scripts/project_points.py` 接受已经取得的 world 点、显式 4×4 矩阵和目标像素，输出
SVG 与归一化坐标 JSON。它不提取游戏网格、不计算蒙皮、不做遮挡测试，也不把截图逆推
成可信骨架；其 `visible` 标签必须来自调用者的实际检查。缺相机数据时先做标注图并注明。

### 眼睛

“两眼统一目标”不能简化为两只瞳孔在眼眶包围盒中具有完全一样的归一化偏移。透视、眼球
大小、眼裂不对称和遮挡都影响视觉。先用完整画面判断，再用头平面与投影辅助；黑瞳孔、
虹膜分别测量，不以镜头外不可见的部分抵消视觉偏差。死鱼眼通常需要较平的边缘和可读的
瞳孔；不能只缩窄眼裂，把黑瞳孔藏到上眼皮后面。

### 嘴与眼镜

嘴中线相对头部中线，嘴角高低相对头平面判断，不能直接把倾斜镜头里的嘴拉成水平。
眼镜桥不要遮成一条“假嘴”；按实际镜头上下小移，复查说话、转头和手接触。
对最终微笑的静态位移全段套用，可能在中间说话帧让上下唇交换。应逐姿态拟合并限制
面朝向翻转、上下唇间距和局部位移。high/low 用各自基线，不共享绝对嘴部高度。

数学无翻面只是局部几何条件。完整动作、牙舌口腔、镜架遮挡和艺术效果仍需看视频。
