# 可复查的角色动作重定向流程

适用于已有源游戏骨架、动作及替换角色的工程。目标是保留源动作的节奏、缩放和游戏事件，
把动作搬到替换角色的实际关节与体型上。骨名一致和模型可显示只是接口条件，不能证明已适配。

完整案例、源工程脚本角色和不需要游戏资源的数学演练见
[Gold → Slayer 重定向 example](gold-retarget-example.md)。案例数字属于该工程，
其中的开发版UE实机检查不等于正式Cook包或每个对局分支都已验收。

## 1. 建立真实状态覆盖

从实际运行的动画表读取 `state/name → AnimSequence`，再对照源脚本的动作、cell、loop、
显隐、模型切换和返回路径。记录脚本哈希。仅按文件编号、目录中的文件数或 `cs` 后缀分组会漏掉
备用待机、起步、追击和换模分支；脚本块中的字面引用也不等于动态分支已执行。

保留每个入口的源资源、目标资源、骨架/绑定、原帧数/时长、已测试输入与尚未覆盖项。
普通动作、演出动作和专用身体可以分阶段制作，但未做的入口不能被计为重定向完成。

## 2. 提取并验证原 T/Q/S

- 保存原始位移T、四元数旋转Q、三轴缩放S、轨道到骨索引映射、参考绑定及缺轨策略。
- 若查看器/PSA导出只提供位置和旋转，另从源动画raw轨道取缩放，并交叉核对P/Q和骨名。
- 应用源工程的动画平移策略，例如“仅旋转骨”与允许位移骨列表。不能把所有骨平移清零。
- 用匹配引擎的父子T/Q/S规则重建源world与skin变换；明确单位、轴向、四元数约定。
- 保存原raw索引、真实采样时钟、SeqLength及相同姿态的保持帧。去重可节省计算，不能改变时间。

## 3. 按替换角色实际关节做运输

源参考绑定与目标自然REST关节分别保存。由源 `world × inverse(bind)` 得到动作增量，
围绕目标真实关节运输旋转/缩放，并按实际骨段长度处理平移残量；不要仅把源世界骨点塞给目标。
衣物/辅助骨保留其相对已适配父级的运动，检查哪些新附件实际消费了这些骨。

保留作者非均匀缩放、隐藏用近零缩放及夸张伸长，不统一重置为1。也不要无条件保留每个helper
压缩在新形体上的视觉后果：源宽裤可能有独立衣骨补偿，而替换裸腿主要受皮肤helper控制，
同一压缩会显得过细。先按相同动作阶段比较源与目标的实际表面/权重，再做局部适配。

接触IK只对真实支撑脚使用。空中、浮空、墙面和倒地状态不能因“本片最低脚点”而锁在地面。
步行支撑要结合源脚高度、速度、动作状态和两脚相对关系。宽阈值误把抬起的一脚判为支撑，
可能让双支撑求解跳到远处的另一支解；核root偏移、骨长、实际足底与循环交界，不能事后给
root补一段平滑线掩盖错误。保留源停帧，不以全局插值修复重定向失败。

手部须分别核旋转/缩放和关节点。巨大手指射线可能来自指节pivot相对目标手掌错位，未必是
末端IK或twist角错。射线消失后仍检查掌指根与腕部权重；相邻短边两端100%分给不同指骨、
新增手套点继承远处旧腕点权重，仍可能留下局部裂缝。

## 4. 输出引擎能精确表达的局部轨道

先用FBX往返验证；有非均匀父缩放时，通用矩阵逆乘再分解可能产生shear，而目标引擎的
`FTransform`并不按同一方式组合。发生实际差异时，优先直接按引擎T/Q/S语义生成local轨道：

```text
Qlocal = inverse(Qparent) * Qworld
Slocal = Sworld / Sparent
Tlocal = rotate(inverse(Qparent), Tworld - Tparent) / Sparent

Tworld = Tparent + rotate(Qparent, Sparent * Tlocal)
Qworld = Qparent * Qlocal
Sworld = Sparent * Slocal
```

这些式子要求已确认目标引擎约定、单位与轴。零父缩放的0/0分量没有唯一解，可保留已知源local
相应分量，再以重建world断言检查；不能偷偷把父scale改1。统一四元数半球只解决符号表示，
不意味着要平滑原停帧。任何从一般矩阵投影到T/Q/S的误差都要单列并关联实际加权骨。

支持的引擎API可作为经过证明的FBX替代：复制原AnimSequence，按骨名写raw轨道，保留原
曲线/通知，设置确切帧数、时长和插值类型，再标记raw修改、重压缩和保存。API/ABI及骨映射
必须匹配当前构建，不能把某台机器的地址、结构偏移或导出符号直接当跨版本接口。

保存后用独立进程重开，按骨名读实际raw P/Q/S、帧数、绑定与插值，重建world并和目标比较。
压缩可能把几乎不变的scale轨道折成常量；报告实际误差，不能把近似保持写为逐字节一致。
还要检查正常压缩播放，不以编辑器RAW开关代替最终路径。

## 5. 接入游戏的完整显示生命周期

实际动画表必须引用新资源，并读回确认。替换角色可能由身体、独立头、披风、饰品组成；
每个显示部件应使用正确driver和同一时间。共有接缝两侧应共享绑定权重，避免静态能接上、
一动就分离。

动态材质、模型显隐、溶解、变体切换是动作流程的一部分：

- 独立显示组件若永远可见，会把原版闪现dash变成可见平移。同步源逻辑显隐/材质事件，
  不把为了隐藏原网格而手动设置的render-pass标志误当成游戏意图。
- 爆衣/专用身体切换要列明活动mesh、骨架、动画表、出现及恢复事件；常态和专用身体不能
  永远跟同一个已隐藏driver。按用户指定身体版本切换，不能以“隐藏衣服”掩盖身体动作未适配。
- 脱离角色的衣物残留/飞片要从实际释放前的替换角色姿态建立，转换到真实粒子发射器的
  局部或世界空间，再保留源运动、寿命和显隐。把REST衣物按源碎块中心粗摆，会留下姿势
  不符的空衣服。检查角色离开后碎片留在原位置还是错误跟随；通用碎屑保原尺度/破碎轮廓，
  不把整块装饰裙片贴到每个粒子。主角色、独立残像、衣物残留、碎屑及冲击拖尾分别验证。
- 追击/特写可能切换高低头或给头部挂点额外旋转。先核活跃头、component/socket/root变换，
  再判断是否要做表情；不能为了修挂接漂移去重塑已认可REST脸。
- 服饰遮罩要在base/outline/shadow/decal等实际使用pass保持一致，保原溶解逻辑；不要把
  有其它含义的Base alpha当通用透明度。

新材质图保存成功、参数读回正确仍不证明GPU编译通过。逐项检查所改材质的编译日志；
default-material fallback会使黑块或未裁显看起来像几何/outline故障。在当前UE构建中，
PreSkinnedPosition之类仅顶点阶段可用的数据若要参与像素OpacityMask，应经支持的插值路径
传到像素阶段，不能直接接后就凭节点存在宣布成功。材质有效后再做同姿态pass隔离。

隔离导入目录及会被修改的Skeleton/Material依赖。目录链接不等于只读；导入器可能自动重建
经链接指向的源Skeleton。先解析真实目标路径，复制所有潜在写入包，并在操作前后核源哈希。

## 6. 用实际操作与摄影验收

主证据为游戏摄像机、完整材质、身体动作和同一时刻真实披风动作。辅助自由视图只能定位问题。
至少覆盖初始/备用待机、移动和停步、连续多个循环、蹲起、跳落、近远攻击、受击及回归；
专用变体另测切换/恢复。后退一小段不证明连续按住不会在loop边界跳变。

记录实际活跃component的动画引用、序列时间与摄像机，而非只记请求tick。不同组件可能有同名
AnimInstance，日志须按outer筛选。测试按键以当前编译分支和实际消费为准；编辑器开发版本
与零售版键位可能不同，未出招不能当作出招成功。

可操作启动器须实际运行：确认宏被解析、模型/材质赋值真正执行、窗口可响应并持续显示当前角色。
语法/依赖检查不能替代画面。验证输入与自动截图放在测试入口；交给作者的入口保留自由控制。

## 案例工作区的具体脚本入口

下列是本流程来源工程中的相对路径与接口说明，**不是harness已安装的可直接运行命令**。
它们含案例适配条件；换项目时实现等价输入/输出，不复制固定角色路径、骨数、阈值或ABI。
公开harness不包含第三方模型/游戏资源，项目自己的来源映射与哈希留在项目报告。

| 步骤 | 来源工程入口 | 关键输出 |
|---|---|---|
| 状态/动画覆盖 | `scripts/classify_ordinary_coverage_r193.py` | `ordinary_coverage.json`：实际动画表与BBS状态引用对应 |
| 原动作清点/提取 | `work/ordinary_retarget_r193/inventory_export_sources.py`、`decode_sources.py` | 原raw P/Q/S、bind、允许位移规则、raw/时间/hold与源哈希 |
| 已有接触基础 | `scripts/motion_solver_r129e.py` | 自然目标骨段、支撑分类与足底约束；阈值按新动作检验 |
| 通用比例运输 | `work/ordinary_retarget_r193/retarget_solver.py`、`solve_all_ordinary.py` | 目标world骨矩阵、实际缩放与支撑修正日志 |
| 早期可查FBX路径 | `scripts/export_body_native_r142.py`、`export_body_idle_r146.py`、`work/ordinary_retarget_r193/export_motion.py` | 骨/单位/hold明确的FBX；先验证非均匀缩放运输 |
| 精确UE局部轨道 | `work/ordinary_retarget_r193/build_ue_tqs.py` | local T/Q/S二进制、骨名、目标world及往返误差 |
| 原生写入/保存 | `work/interactive_demo_r191/write_ue_actions.py` | 复制原clip后按名AddNewRawTrack、重压缩的新包 |
| 独立原生读回 | 同目录 `read_action_data.py`、`verify_action_data.py`、`verify_ue_raw_exact.py` | 实际P/Q/S、帧数/时长、压缩误差与绑定核对 |
| 动画路由/完整总装 | 同目录 `build_action_routes.py`、`build_runtime.py` | 新public动画表、全组件/材质/driver接入；显隐/变体按上文扩展 |
| 真实输入/摄影 | 同目录 `runtime_clock_probe.py`、`test_transitions.py`、`encode_battle_videos.py` | 实际序列时间、game-camera完整片段与正常速度视频 |

此表不是“以上脚本一跑就全部通过”。已有工程后来实际暴露过抬脚误判双支撑、helper压薄缺少
源衣物补偿、独立显示未同步闪现显隐，以及专用身体/高头挂接漏接；这些均需按证据回到对应层修。
