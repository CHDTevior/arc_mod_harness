# 纹理清晰度、UV 与材质：Chaos 实际问题及解决路线

本页将已定位的原因、通过的阶段与剩余限制分开。H 编号见仓库证据索引；数字是本项目
记录，不是通用引擎参数。展示效果优先看实际游戏相机，棋盘格、灰模、纯色和放大图用于诊断。

## 1. 明明合图 8K，纹身和小字仍不清晰 [H37]

当时原 COS 图为 2K，身体工作图为 4K，旧整套图集为 8K；游戏配置实际纹理预算另有限制。
整张图的边长不能代表胸口一小段文字或手背纹样分到了多少像素。

另一个实际原因是旧迁移算法：双线性取样后又把颜色硬分为四种纯色，把原抗锯齿的连续
覆盖信息抹掉了。放大输出无法恢复被这一步丢掉的边缘。

修复试验保留原调色之间的连续比例，从同一源 UV 和投影重新采样；模型、镜头和尺寸不变
做 A/B。没有重画字形，也没有用 AI 放大冒充恢复。该记录只是工作图试验；手部、重排图集
和游戏实际下采样后来分别检查。源文字本来像素少的限制不能说已经消失。

**复用办法：** 依次量源细节、目标 UV 占地和屏幕大小；追查每次采样/调色/烘焙，修复
最早的信息损失。实际剩余细节不足时，再选择增加图岛预算、重绘作者批准的图案或减少细节。

## 2. 引擎出现大片色带，不是先重做 UV [H38]

该次隔离原生场景普通 streaming 启动时，纹理最大为 8192，但实际 GPU 驻留只有 64×64。
在同场景缓存预热、关闭该预览的 streaming 后，驻留升到 8192×8192，大片色带消失。
这组 A/B 将原因定位到启动 mip 驻留，覆盖了早先“可能 shader/UV 错了”的未定假设。

同时核查了源 UV、生产 FBX、原生重导出、材质实际覆盖和 full-precision UV；半精度实验
确实显示细小图岛可能受损，却没复现大片色带，且本次三个实际网格已经启用全精度。
因此“改全精度 UV 修好色带”是错误复盘。

**范围：** 关闭 streaming 是隔离诊断，不作为让朋友全局禁用 streaming 的交付方案。
隔离预览 8K 驻留也不代表原游戏保持 8K；最终需按本游戏预算重新布局并验证实际 mip。

## 3. UV 零重叠还不够：出界、拉伸、岛间距与覆盖 [H39]

连续身体 UV 经多轮展开。R05 保存保护通过、声称零重叠，但 224 个修复面仍在图域外，
因此被拒收。R06 显式选中全部 UV 后排布，增加保存前域界断言和独立读回检查。

R06 保留胸腹大岛，仅处理有证据的局部重叠；28 对象、24 网格的原数据保持，新增指定
身体/颈部 UV。18,946 个三角面在 0–1 内，无正面积重叠、翻转或退化。另量岛间距、
边框距离和最差方向的密度；实际棋盘格检查发现并确认严重拇指压缩的改善。

这只接受作者 UV 基础，不等于纹身或正式 shader 通过。新增层当时并非 active/render UV，
后续材质必须明确读它，再安排最终导出通道，不能“UV 在文件里”就认为游戏在用。

**复用检查：** 域界、重叠（区分有意镜像）、方向/退化、各向拉伸、texel 密度、边距、
实际像素覆盖、保存后读回，并保留原拓扑/法线/权重。图岛有面积不等于小三角形有有效像素。

## 4. 独立身体 UV 不能直接覆盖共享图集 [H40]

实际角色由身体、外套、高低头、独立光环等资源组成；当时保留的材料路由共用 COS 图域。
不能让新身体独占一张 4K 的 0–1，再让旧头衣也各占满 0–1，却继续共用同一采样图。

最后路线是保留身体专用 UV 作为制作坐标、保留未改头饰的好岛，将它们组合进同一个生产
图域，避免全角色再 smart-project。若改成独立身体材质则必须同步真实实例、运行时材料表
和依赖；引擎并非只支持一张图，只是原保留路线不能凭新增 Blender 材质名自动变成多图。

原 SkeletalMesh 的空材料引用也不能直接判为缺图：该角色通过运行时材料表赋材质。
应追踪 **mesh/section → 状态材料表 → 实例父链 → Texture 参数 → UV 通道**；FBX 名字或
槽数量相同不足以证明运行路由相同。旧 uncooked 表与当前 cooked 还存在版本差异。

## 5. 内衬颜色跳边、发梢黑点和微小图岛 [H41、H43]

在共享图集中，外套真实相邻面可能属于不同材料；低密度岛内部直接画两种填色，边界
取样可能落错语义。R04 只移动有证据的边界面及缺少有效材料 ID 的面，共 541 多边形，
分到有采样余量的小格中，保留其他好岛和原 UV，避免全图再打乱。

随后单独核对真实栅格材料 ID、覆盖与合成结果；不能把数学上“有像素中心”说成烘焙已经
正确。R03 source-base 检查记录确认内衬边界、手部抗锯齿及发梢黑点改善；冻结的是共享
4K 源图和布局，后续仍要完整 companion maps、原生材料和实际游戏检查。

padding 必须按邻接与材料归属生成，不能把身体颜色扩散到衣服。验证最差 mip、压缩后
边缘与实际镜头；8K 的小空隙未必能在 4K 或更低 mip 保留下来。

## 6. 手部重新采样：AA 的 alpha 不是游戏控制 alpha [H42]

手部采用原场 2×2 子样本重新查询，不放大、模糊或重绘旧 PNG。仅实际命中的样本参与
RGB 均值，防止把“没有命中”的零值算进来制造黑边；共享边相邻三角的有效样本一起累积。

合成只替换中心归属手区的指定像素，排除越到腕外身体的子样本。采样结果的覆盖 alpha
只是辅助统计，**保留游戏原控制 alpha**，不能拿 AA 覆盖率直接盖掉材质控制通道。
少数四点均未命中的小像素保留原中心烘焙，并记录例外；不伪造样本来声称全覆盖。

## 7. 材质的 UV、颜色空间、alpha 和法线必须成套看 [H09、H40]

以下是本次 COS 实际材料链的结论，不应复制成所有游戏/角色参数：

| 项目 | 当时的检查与处理 |
|---|---|
| Base、SSS、ILM、Detail、OLM、Decal | 分别对应本色、阴影色和各类控制；改图域须同步所有实际采样图，不能只迁 Base |
| UV 通道 | 主族 Base/SSS/ILM/OLM 使用 UV0，Detail 使用 UV1；Decal 另有材质路径。保留原通道数据与导出层序，按实际节点验证 |
| 颜色空间 | 原六图 SRGB=false；原 shader 有 Power(2.2)。源图数值复用和线性烘焙结果编码分开，控制通道不做 gamma；避免重复编码 |
| 顶点控制色 | FBX 使用 LINEAR；曾发现 SRGB 导出将控制 G=0.4 改成约 0.667，修正后原生读回核对 |
| alpha | 身体 Base A 和 SSS A 有控制含义；镜片 Base A 参与透明度。不能统一设 1、把 alpha 当无用或把 AA alpha 当控制图 |
| PNG 导入 | 在隔离项目关闭 FillPNGZeroAlpha，避免导入器填改 A=0 处 RGB；查看器导出的 alpha 不代替原 SourceArt/压缩像素检查 |
| 镜片 | 高低头专用 section、实例父链、原 matcap 与脚本透明度参数都需保留；不能仅沿用旧镜片 UV0 去采新图集 |
| 自定义法线/切线 | 保留并适配作者明暗控制；本次 ArcSys 自定义 Tangents 不等于通用 PBR TBN，不能因 determinant 异常就当坏网格全重算 |

皮肤不够有光泽时先比较实际 shader、法线和高光控制。R09.2 参考 Jam 后调整自身皮肤
ILM 的高光强度/阈值相关通道，保留阴影/黑线控制，并核对导入与 GPU 解码；多色一起
检查。鞋面、鞋底、鞋带和眼镜另做配色归属。全配色黑枪则是共享 detail 被身体改动影响，
通过独立枪 detail 与实例链重定向修复。[H11、H16、H17]

## 8. 最有效的检查顺序

1. 固定实际镜头、模型、姿态与光照，先判断症状：模糊、锯齿、色带、串色、错影或透明度。
2. 从原素材到制作图看细节是否已经丢失，再查实际 UV/图域/通道；用棋盘格和 ID 图分辨。
3. 从导入材料表追到真实采样纹理，查颜色空间、alpha、法线/顶点色与 shader 参数。
4. 查原生 SourceArt、Cook 格式、top mip 和实际 GPU 驻留。仅有编辑器 8K 标题不算。
5. 每次只改能区分当前假设的部分，同镜头 A/B；通过后检查相关配色、所有消费者和受影响
   动作。最后看游戏原镜头及最终包，宣传图在这些修复稳定后再生成。

人类提供“这里糊/这里不亮”的局部截图与目标参考，也决定是否值得提高细节；AI 负责定位
哪一层丢信息、量覆盖和保持其他区域。不要让新手在不了解证据时选择 gamma 或 UV 精度。
用 [表面审计表](../templates/surface-audit.md) 留下输入、修复与真实验收范围。
