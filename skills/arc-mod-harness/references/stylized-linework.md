适用：角色外缘缺黑线、黑壳膨胀、内部结构线模糊，以及新增部件接入 ASW 材质。
配合 [纹理专题](texture-uv-material.md) 和 [动画与作者法线](animation-presentation.md)。

私有合同审计的相对标识与摘要见 [证据索引](gold-demo-evidence.json) G22。

## 先区分三类线

1. **外轮廓**：轮廓壳或原生附加 pass，反向剔面并沿专门方向膨胀。方向、宽度、深度偏移、材质和相机共同决定结果。
2. **内部结构线**：用专用 UV/控制图表达作者需要的结构，通道由实际 shader 决定。不能因为“缺描边”，就在已有 Base 或头发 Detail 上随意画长黑条。
3. **Motomura lines**：资料中的方法借助重复顶点及专门 UV 布局，让几何上的线宽变化映射到规整的纹理边界。关键是网格与 UV 配合，不是任意一张黑线贴图或屏幕后处理。近景仍受采样影响，不能承诺无限分辨率。

本项目作者拒绝了直接在原有头发纹理上补条纹的候选。保留原贴图；先接通原生外轮廓。若以后需要内部线，先按镜头标明位置与粗细，再创建独立、可回退的结构/UV 候选。没有完成该制作就不能称已实现 Motomura lines。

## 原生外轮廓：制作与核验

1. **记录真实消费者。** 列出主体、独立 outline、clone、物理头发、残像及状态替换。确认是单 mesh 附加 pass，还是独立反绕序壳；两条路线不能无意叠加。
2. **分开方向语义。** 保留着色 `NormalZ`；膨胀方向可从合适的作者方向构建，再写入 `Tangents`（CORNER / FLOAT_VECTOR）。普通 UV 切线往往垂直于 N，不是这条描边路线要的方向。不要把复制 N 当作所有接缝的最终艺术答案。
3. **验证传递。** ASW 导出后核 `LayerElementTangent` 及目标导入所需的 Binormal，采用匹配版本的导入设置。检查 build settings 是否重新计算/覆盖 TangentX。普通 UE 回导 FBX 可能不包含原 buffer 的 X/Y，因此需直接读 native vertex buffer。
4. **核对 section。** 当前定制工程的 `OutlineMaterialIndex` 按 section 查询：`-1` 表示无附加描边，`<=-2` 隐藏，非负值指向描边材料槽。只在确认该实现时使用这些语义；独立壳的 index 为 `-1` 不必然是错误。
5. **局部调宽度。** VC Alpha 是顶点控制数据，区别于贴图透明度。Chaos 曾只改三束新发 Alpha 为 `127/255`，并保持 RGB；其原生公式下 A=1 与 A=.5 的宽度比约 2.43。它不是所有物体应统一刷成127的理由。记录 FOV、全局 scale、局部 alpha、深度和描边色。
6. **保护与比较。** 按有序三角角及全部有效属性匹配 P/N/UV/VC/W，不把渲染顶点拆并数量不同直接判为改形；记录量化误差。先用游戏常用镜头与演出近景做同帧 A/B，再看受影响的动作过渡。

当前 Gold 的诊断曾发现：头发输入带普通 UV 切线，身体输入缺切线层；实际旧 buffer 的 X 与 Z 垂直。方向候选已在原生 buffer 中读到目标方向，但画面验收是另外一步。这条记录不表示全部衣服、头发和表情描边已获接受。

后续R209代表镜头已完成：真实暂停的idle与5P转身同姿比较，方向修复加局部outline宽度/线色改善手套指缝、耳/额侧及靴边，被选为demo候选。仍使用既有独立反绕序壳，没有冒称已迁移额外section pass；脸/皮肤/base图不随之加粗或改色。

**具体制作例的I/O**（私有工程相对路径，不分发原资产）：

- `work/parallel_r209/outline/fbx_tangent_audit.json`：源FBX的P/N/T及层注册 → 普通UV切线与缺层诊断。
- `work/parallel_r209/outline/handoff/PATCH_MANIFEST.json`：新方向FBX、native导入资源及保护摘要 → 最终消费者和哈希；包含native UV合并例外，不能声称全UV逐字节不变。
- `work/parallel_r209/outline/handoff/gold_outline_r209.h`：在body/物理hair材质的每帧source复制与五图恢复之后，对指定outline槽写局部宽度与必经线色参数。此前`MulColor`诊断被未开启的静态开关忽略，故不可拿其无变化推断颜色原因。
- `work/parallel_r209/outline/handoff/same_pose_evidence.json`：真实GameState暂停、相机与body/head anchor读回、4K全图及原像素裁图 → 同姿证据。没有把anchor相同说成全骨逐一验证。

本例实际使用原生LOD顶点读回及画面对照，并非RenderDoc GPU捕获。方向变化会合并原UV切线分裂的重复点；应按有序角属性对比并记录导入容差造成的UV差异，不能只核总点数。

### 黑块的两个不同例子

- **壳过宽**：几何姿态正确，但额外膨胀遮住相邻部件。通过同姿态关该 outline、改局部宽度及核方向区分；不能因为组件 `Visible=true` 就声称镜片在最终画面可见。
- **蒙皮折叠**：差异缩放把新发束折到一起，暴露黑色背面。Chaos 局部权重修正曾消除一个胜利采样中的大面积翻面；只调 alpha 不能修复折叠，也不能外推全部动作已通过。

## PDF 中另外两点如何落地

**法线与明暗**：按实际游戏灯向、阈值、作者 N 与 morph N 增量逐层定位。保留有意的鼻侧、唇下、下颌阴影；“减少碎影”不等于抹去阴影。资料的脸部示意用于理解明暗设计，当前模型仍沿用已核验的作者法线合同。

**颜色与控制图**：图案用不带截图明暗的本色，暗部色、高光强度/形状、描线控制各归实际 shader 路径。PDF 的 SSS/ILM 名称及推测公式不能直接写成通用通道表；逐一检查当前材质父链、采样 UV、颜色空间及动态参数。徽章锯齿应修源轮廓与有效像素预算，不能用模糊或高分辨率空画布冒充细节。

## 交付时保存什么

保存输入摘要、构建脚本与参数、导入设置、buffer/section 读回、同镜头全图及原像素裁剪，并列明未通过的帧。静态材质检查可在隔离 UE 场景使用游戏 shader/光照快速完成；变形、摄像机、隐藏与换模型须用真实动画路线。最终 demo 使用同一组已核对的资产，Cook 后的声明需另外有 Cook 数据证据。
